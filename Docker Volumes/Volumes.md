### Docker Volumes

* Docker containers are easiest to use with stateless applications because their file-systems are ephemeral in nature. Changes made to a container's environment are lost when the containers stops, crashes or get replaced

* You can dockerize stateful applications such as databases and file servers by attaching volumes to your containers. Volumes provide persistent storage that is independent of individual containers.

### Bind Mounts

* These type of volume is used when you wish to access the files or directories from both containers as well as the host

* This should be used for development purposes as you may need to access the files on both host syste, and the container

#### Syntax

`docker run -v /host/path:/container/path`

### Named Volumes

* This are the preferred mechanism for persisting data generated by and used by Docker containers

* Named volumes are managed by Docker. It can be shared among different containers

#### Syntax

`docker run --mount type=volume,src=<volume-name>,dst=<mount-path>`

In general, `--mount` is preferred. The main difference is that the `--mount` flag is more explicit and supports all the available options
